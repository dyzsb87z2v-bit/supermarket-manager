# مدیریت سوپرمارکت (نسخهٔ ۰.۱)

یک وب‌اپ ساده برای مدیریت موجودی، فروش، سفارش و گزارش یک سوپرمارکت کوچک. **صفر هزینه، صفر وابستگی** (فقط HTML/CSS/JavaScript)، مناسب موبایل، قابل نصب روی صفحهٔ اصلی گوشی (PWA) و **کار آفلاین**.

> این پوشه کاملاً مستقل است و هیچ ارتباطی با پروژهٔ دیگر داخل این مخزن (Berlin Rent Hunter) ندارد. بهتر است بعداً در یک مخزن جداگانه قرار بگیرد.

## چه چیزی ساخته و آزمایش شده

| ۲. موجودی و ثبت ورود، فروش، ضایعات، اصلاح موجودی (فروش بیش از موجودی رد می‌شود) | ✅ |

### محدودیت‌ها و قواعد رعایت‌شده
- **داده‌های نمونه** ساختگی‌اند (بارکد از محدودهٔ داخلی EAN 200–299، تأمین‌کنندگان خیالی) و در یک فضای کاملاً جدا («نمونه») نگه‌داری می‌شوند. کد اجازه نمی‌دهد نمونه در «واقعی» نوشته شود یا پشتیبان نمونه در واقعی بازگردانی شود (تست شده).
- **اطلاعات مشتری** هیچ‌جا جمع نمی‌شود؛ فیلدی برای آن وجود ندارد.
- **سفارش خودکار وجود ندارد.** فقط متن آلمانیِ پیشنهادی ساخته می‌شود که خودتان کپی و ارسال می‌کنید.
- هیچ سرویس خارجی، API، CDN یا فونت اینترنتی استفاده نشده؛ همهٔ فایل‌ها از خود برنامه لود می‌شوند.
- قیمت‌ها با عدد صحیح سنت ذخیره می‌شوند. مالیات (۷٪/۱۹٪) در محاسبات **در نظر گرفته نشده**؛ «سود خام» = فروش − بهای خرید ثبت‌شده.
- پیش‌بینی ساده است: روزهایی که کالا تمام شده بوده در میانگین جبران نمی‌شود (تقاضای کالاهای پرتمام‌شونده کمتر از واقع برآورد می‌شود). هیچ مدل فصلی/تعطیلات ندارد.
- تاریخ انقضای هر محموله از «ورود کالا» می‌آید؛ اگر موقع ورود وارد نشود، هشداری نمی‌دهد.

## فرمول پیشنهاد سفارش
```
میانگین روزانه = فروش N روز اخیر ÷ تعداد روزهای تاریخچه   (N پیش‌فرض ۲۸؛ حداقل ۷ روز مبنا)
نقطهٔ سفارش    = میانگین × زمان‌تحویل + حداقل‌موجودی
هدف            = میانگین × (زمان‌تحویل + روزهای پوشش) + حداقل‌موجودی      (پوشش پیش‌فرض ۷ روز)
اگر موجودی ≤ نقطهٔ سفارش:  مقدار = هدف − موجودی، گردشده به بالا تا مضرب «اندازهٔ بسته»
```

## اجرا

**برای استفادهٔ واقعی روی موبایل** فایل‌ها باید روی یک آدرس HTTPS قرار بگیرند (برای نصب PWA و کار آفلاین لازم است). هاست‌های استاتیک رایگان مثل GitHub Pages (فقط مخزن عمومی)، Cloudflare Pages یا Netlify کار می‌کنند، فقط پوشهٔ `supermarket-manager` را منتشر کنید. **من هیچ‌کدام را راه‌اندازی یا آزمایش نکرده‌ام.** نکته: داده‌ها فقط داخل مرورگرِ همان گوشی می‌ماند، پس از آدرس عمومی بودن اپ نگران افشای داده نباشید؛ ولی مرتب «پشتیبان» بگیرید.

**روی کامپیوتر برای آزمایش:**
```bash
cd supermarket-manager
python3 -m http.server 8080        # سپس http://localhost:8080 را باز کنید
```

**تست‌ها:**
```bash
npm test                           # ۳۱ تست منطق (Node ≥ 20، بدون نصب پکیج)
node tests/e2e-smoke.cjs           # اختیاری: تست مرورگری (نیاز به Playwright)
```

## ساختار
```
index.html, css/, icons/, manifest.webmanifest, sw.js      ← پوستهٔ PWA (sw.js: عدد VERSION را با هر تغییر فایل‌ها بالا ببرید)
src/core/   منطق خالص و تست‌پذیر: model, inventory, forecast, alerts, reports, csv, io, demo, store
src/ui/     رابط: app.js (صفحه‌ها)، i18n.js (متن‌های فارسی)، dom.js
tests/      تست‌های واحد (node --test) و تست مرورگر
```

## ستون‌های CSV
- **کالاها:** `barcode; name_de; name_tr; category; supplier; buy_price; sell_price; unit; min_stock; pack_size; active` (نام ستون به آلمانی/ترکی هم پذیرفته می‌شود: Artikel، EK، VK، Mindestbestand، Barkod …). ورود مجدد بر اساس بارکد «به‌روزرسانی» می‌کند.
- **فروش / ورود کالا:** `date; barcode; qty` و اختیاری: `unit_price; unit_cost; expiry; type; branch; note`. تاریخ `2026-03-31` یا `31.03.2026`.
- ورود CSV «همه یا هیچ» است: اگر یک ردیف خطا داشته باشد هیچ‌چیز وارد نمی‌شود و شمارهٔ ردیف خطا نشان داده می‌شود (تا با ورود دوباره، رکوردها تکراری نشوند).
